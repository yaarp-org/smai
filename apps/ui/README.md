# `@smai/ui` — SMAI single-page application

The user-facing SPA for SMAI v2. Consumes the JSON API published by `smai-api`
(see `~/projects/Yaarp/designs/smai/11-api.md`) and is served in production by
the `smai ui` verb (`12-ui-process.md`). Stack and rationale live in
`13-frontend.md`.

This package is scaffolding only at Task 4.M1 — every route renders a
placeholder. Real content lands in 4.M3+; see `Status` below.

## Dev workflow

Two terminals (canonical, per `12-ui-process.md` §8):

```bash
# Terminal 1 — FastAPI dev server on :8000
cd packages/smai-api
uv run uvicorn smai_api.app:make_app --factory --reload --port 8000

# Terminal 2 — Vite dev server on :5173 with HMR
cd apps/ui
pnpm install     # first run only
pnpm dev
```

Vite proxies `/api/*` → `http://127.0.0.1:8000` per `vite.config.ts`, so the
SPA always uses same-origin URLs. No CORS, no env-switched base URL.

Open `http://localhost:5173` after `pnpm dev` boots.

The API server is not strictly required to view the SPA in 4.M1 (every route
is a placeholder, no fetch happens). It becomes required once 4.M2 lands the
generated client and 4.M3 wires real queries.

## Production build

```bash
cd apps/ui
pnpm build       # → apps/ui/dist/
```

`dist/` contains `index.html` plus hashed `assets/`. Task 4.N1 packages this
directory as the `smai-ui` Python wheel's `static_spa/` resource; `smai-api`
mounts it at `/` per `12-ui-process.md` §8.2.

## Gates

```bash
pnpm typecheck       # tsc -b --noEmit
pnpm lint            # eslint .
pnpm format:check    # prettier --check .
pnpm build           # tsc -b && vite build
```

## Type-safe API client (`pnpm codegen`)

The SPA reaches `smai-api` through a fully-typed client generated from the
FastAPI app's OpenAPI 3.1 spec. Per `13-frontend.md` §5, this is a strict
compile-time gate: paths, parameters, and response bodies that drift from the
API surface show up as TypeScript errors before runtime.

```bash
pnpm codegen   # writes src/lib/api/generated/api-types.ts
```

Under the hood, `codegen` runs `tools/dump_openapi.py` (in-process, no port
held) and pipes the spec through `openapi-typescript`. No FastAPI server
needs to be running. Source: `apps/ui/package.json` `scripts.codegen`.

**When to run it:**

- After pulling changes that touch `packages/smai-api/` or `packages/smai-api-spec/`.
- After editing those packages locally (before exercising the SPA against
  the changes).

**What's committed.** The generated file at `src/lib/api/generated/api-types.ts`
**is checked in**, not gitignored. Treat regeneration as a manual step paired
with the diff in your PR. A future CI gate (post-M5 backlog item per
`13-frontend.md` §5.4) will rerun `pnpm codegen` and `git diff --exit-code`
the result, failing if a contributor edits `smai-api` without regenerating.
For M5 the discipline is local + reviewer.

**Using the client.** Import `$api` from `@/lib/api/client` and call the
TanStack Query hooks (`$api.useQuery`, `$api.useMutation`). See
`src/routes/system.tsx` for a worked sample against `GET /api/v1/system/version`.

The `routeTree.gen.ts` file at `src/routeTree.gen.ts` is auto-generated by the
`@tanstack/router-plugin` Vite plugin from filenames in `src/routes/`. It is
git-ignored and regenerates on `pnpm dev` / `pnpm build`.

## Adding pages

Create `src/routes/<name>.tsx`:

```tsx
import { createFileRoute } from "@tanstack/react-router";

export const Route = createFileRoute("/<name>")({
  component: MyPage,
});

function MyPage() {
  return <div>...</div>;
}
```

The Topbar nav list lives at `src/components/nav/topbar.tsx`; add an entry
there if the new page needs top-level nav presence.

## Adding shared components

For shadcn primitives, prefer the CLI:

```bash
pnpm dlx shadcn@latest add <component>
```

The shadcn config is `components.json`; new components land under
`src/components/ui/`.

For domain components (state badges, entity cards, etc.), drop them under
`src/components/`.

## Design system

Tailwind 4 CSS-first; the design tokens (per `13-frontend.md` §9.1) live in
`src/styles/globals.css` under `@theme { ... }`. Light defaults; dark via
`@media (prefers-color-scheme: dark)` — no explicit toggle in 4.M1 (per OQ5
inline decision).

The token set covers:

- `--color-bg`, `--color-bg-subtle`, `--color-fg`, `--color-fg-subtle`,
  `--color-border` — surface tokens.
- `--color-accent`, `--color-success`, `--color-warning`, `--color-danger` —
  semantic colors.
- `--color-state-{draft,implementing,implemented,running,evaluating,complete,failed,pending}` —
  per-state badge colors used by `<StateBadge>` (4.M3+).
- `--font-sans`, `--font-mono`.

shadcn primitives (`button`, `card`, `dialog`, etc.) reference the SMAI tokens
through a bridge layer at the top of `globals.css`; replace the bridge entries
to recolor shadcn components.
